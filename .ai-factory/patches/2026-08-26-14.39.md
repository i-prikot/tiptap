# Accept Windows line endings in the publish tag verifier

**Date:** 2026-08-26 14:39
**Files:** scripts/verify-publish-tag.mjs, test/scripts/verify-publish-tag.test.ts
**Severity:** low

## Problem

`node scripts/verify-publish-tag.mjs v0.5.0` rejected the tracked `.npmrc` on
Windows even though it contained only the approved GitHub Packages registry
mapping.

## Root Cause

Git stored `.npmrc` with LF but checked it out with CRLF because
`core.autocrlf=true`. The verifier compared the raw file to an LF-only string,
and its fixture covered only LF.

## Solution

The verifier now accepts exactly the approved mapping with either LF or CRLF
and logs only the detected line-ending style at debug level. Regression tests
cover CRLF acceptance and confirm that an additional credential line is still
rejected without exposing the credential in output.

## Prevention

- Cover platform-specific line endings in tests for tracked configuration files.
- Keep security-sensitive configuration validation exact; do not use `trim()`
  or ignore extra lines.
- Run release verifiers on Windows before creating a release tag.
