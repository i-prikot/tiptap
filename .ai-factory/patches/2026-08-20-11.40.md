# Declare the Hocuspocus retry dependency at the editor boundary

**Date:** 2026-08-20 11:40
**Files:** packages/editor/package.json, package-lock.json, test/package-public-api.mjs
**Severity:** medium

## Problem

Vite could not resolve `@lifeomic/attempt` while prebundling
`@hocuspocus/provider` for the playground.

## Root Cause

The workspace is managed by npm, but `@lifeomic/attempt` was only transitive
through `@hocuspocus/provider`. Its lock entry and installed copy disappeared
during a dependency update, while the editor manifest had no direct invariant
that required npm to retain the runtime package.
The Vite prebundle's inline `@hocuspocus/common` region made the stack trace
look like a common-package import, although the import belongs to provider.

## Solution

Declared `@lifeomic/attempt@^3.1.0` in the runtime dependencies of
`@i-prikot/editor`, the workspace that owns the Hocuspocus integration. Updated
the lockfile through npm and added a package-boundary test that fails if the
dependency is removed from the editor manifest.

## Prevention

- Keep the package-boundary test in CI so lockfile regeneration cannot silently
  return the editor to a transitive-only dependency.
- Use `npm explain <package>` for this npm workspace; do not rely on `pnpm why`
  without an intentional package-manager migration.
- Verify the provider manifest before adding a transitive dependency to a
  workspace application or library.
