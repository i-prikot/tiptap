# Stabilize playground overlay-boundary coverage

**Date:** 2026-08-04 11:35
**Files:** apps/playground/src/App.vue, test/playground/host-overlay-target.test.ts
**Severity:** low

## Problem

The playground CTA could be mounted before its editor-scoped overlay target
was available, leaving the CTA outside that target. The host-boundary test
also timed out while loading unrelated editor exports.

## Root Cause

The template ref for the overlay target is populated after the initial child
render. CtaPopup therefore started without a Teleport target. The test
loaded the full editor public barrel even though NotionEditor was already
stubbed, and its focused scenario had the default ten-second timeout.

## Solution

Mount CtaPopup after the overlay target ref is populated. The host test now
mocks only the public editor values it needs while retaining the real overlay
provider, and gives both integration scenarios the same explicit timeout.

## Prevention

- Mount Teleport consumers only after a required template-ref target exists.
- Keep host integration tests isolated from unrelated public-barrel exports.
- Give browser-like integration scenarios an explicit timeout when they load
  real floating UI dependencies.
