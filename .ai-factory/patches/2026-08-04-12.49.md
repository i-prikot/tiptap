# Windows release verifier loader path resolution

**Date:** 2026-08-04 12:49
**Files:** scripts/release-verifier-test-loader.mjs
**Severity:** medium

## Problem

The release verifier test loader could form an invalid doubled-drive path on
Windows, such as `E:\\E:\\Work\\...`, preventing the shim from loading.

## Root Cause

The loader converted a file URL to its `.pathname` and then passed that
POSIX-style Windows path to `pathToFileURL`. The second conversion treated it
as a relative path and resolved it from the current working directory.

## Solution

The loader now uses the file URL created directly from `import.meta.url`,
without converting through a pathname.

## Prevention

- Keep `URL` values as URLs when resolving ESM loader modules.
- Run release verifier checks on Windows as part of local validation.
