# Local Vitest fell back to an ancestor installation

**Date:** 2026-08-20 18:39
**Files:** `node_modules/.bin/vitest.cmd` (generated local install artifact)
**Severity:** medium

## Problem

`npm run test` failed to start Vitest workers with `ERR_MODULE_NOT_FOUND` because
`happy-dom` could not be resolved. The stack trace loaded Vitest from
`E:/Work/aif-handoff/node_modules` instead of this repository.

## Root Cause

The repository had its local `node_modules/vitest` and `node_modules/happy-dom`
packages, but the generated `node_modules/.bin/vitest.cmd` launcher was missing.
The npm-script `PATH` lookup therefore continued into an ancestor `.bin`
directory and launched an older, unrelated Vitest installation. That
installation resolved optional environment packages relative to the ancestor
and could not see this repository's `happy-dom`.

## Solution

Ran `npm install` from the repository root. npm restored the local Vitest bin
launcher without changing `package.json` or `package-lock.json`. A targeted test
then ran with local Vitest 4.1.11 and resolved happy-dom 20.11.2 correctly.

## Prevention

- When a test stack points outside the repository, inspect the local
  `node_modules/.bin` launcher before changing dependencies.
- Keep local installs reproducible from the checked-in lockfile with `npm ci`
  when a complete clean reinstall is appropriate.
- Verify the selected runner with `node_modules/.bin/vitest.cmd --version` on
  Windows.
