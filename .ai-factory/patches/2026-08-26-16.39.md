# Handle hidden GitHub ruleset bypass actors

**Date:** 2026-08-26 16:39
**Files:** scripts/verify-release-authorization.mjs, .github/workflows/publish.yml, test/scripts/verify-release-authorization.test.ts, test/fixtures/verify-release-authorization/accepted-hidden-bypass/rulesets/1.json, docs/github-packages-token.md
**Severity:** high

## Problem

The trusted publish workflow rejected a correctly configured active `v*` tag
ruleset with `The active v* tag ruleset must bypass only for the i-prikot user.`

## Root Cause

The workflow deliberately uses a read-only `GITHUB_TOKEN`. GitHub may omit the
`bypass_actors` property from ruleset details for that token, but the verifier
converted an omitted property into an empty array and treated it as an invalid
bypass policy. The project plan anticipated this API behavior, while the
consolidated implementation retained the stricter incompatible check and
omitted the administrator bypass attestation.

## Solution

The verifier now accepts only a genuinely absent `bypass_actors` property and
logs that the read-only token hid it. When the property is present, the exact
single-user `i-prikot` always-bypass check remains enforced. The environment-
bound publish job now requires `TINYFY_RELEASE_TAG_BYPASS_ATTESTATION` before
reading package credentials, and the release guide documents the requirement.

## Prevention

- Distinguish an API-redacted property from an explicitly empty or malformed value.
- Keep read-only workflow permissions and use administrator attestation for
  controls the API cannot expose to that token.
- Test both visible and omitted ruleset bypass-actor responses.
- Assert that security attestations run before publish credentials are read.
