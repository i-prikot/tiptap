# Repair editor package artifacts for default Vite consumers

**Date:** 2026-08-05 15:34
**Files:** packages/editor/package.json, packages/editor/tsconfig.json, packages/editor/tsconfig.build.json, packages/editor/vite.config.ts, package.json, scripts/verify-publish-artifacts.mjs, scripts/verify-editor-consumer-build.mjs, .github/workflows/prepare-publish-artifacts.yml, test/package-public-api.mjs, test/scripts/verify-publish-artifacts.test.ts
**Severity:** high

## Problem

The published `@i-prikot/editor` package exposed `style.css` and `styles.css`
as `dist/styles.css`, although Vite emitted `dist/index.css`. Its JavaScript
could also be overwritten by emitting `vue-tsc` project builds, leaving Vue
component output with top-level `await import('vue')` that default Vite targets
do not support.

## Root Cause

Declarations and Vite output shared `dist`, while the root typecheck invoked a
project build that was permitted to emit JavaScript. The export map named the
intended CSS asset rather than the asset Vite actually produced. The release
workflow only checked archive metadata, so neither mismatch was exercised from
a packed consumer installation.

## Solution

Vite now owns JavaScript and emits `index.css`; declarations are emitted only
to `dist/types`. Workspace typechecks are non-emitting. The pre-publish
artifact step verifies every export target in each tarball and performs a
default-target Vite build in a clean consumer installed from the editor and
schema tarballs.

## Prevention

- Keep declaration output outside the Vite library output surface.
- Verify export maps against the files in `npm pack` archives, not only source
  configuration.
- Run a consumer build without aliases or an `esnext` target before publishing.
