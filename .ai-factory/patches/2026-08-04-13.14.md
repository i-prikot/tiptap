# Restore BlockRole normalization and change diagnostics

**Date:** 2026-08-04 13:14
**Files:** packages/schema/src/extensions/block-role.ts
**Severity:** low

## Problem

BlockRole normalization and successful direct role changes completed without
emitting their diagnostic events. The schema extension tests expected a single
normalization debug event and a typed role-change info event, so coverage failed.

## Root Cause

The extension assembled normalization statistics and a typed successful result,
but returned after dispatching each transaction without passing those values to
the existing console diagnostics contract.

## Solution

Emit the expected debug event after scheduled normalization and when an
append-transaction normalization is created. Emit the expected info event after
a direct role change is dispatched, using the typed result fields. Route all
diagnostics through the shared `createLogger('BlockRole')` utility, which owns
console interaction and log-level policy. Configure its minimum level as
`debug` so the required diagnostics remain observable when CI does not expose
the Vite development flag.

## Prevention

- Preserve event assertions for successful mutation paths as well as rejection paths.
- Keep diagnostics limited to metadata and never include document content.
- Use the schema logger instead of direct console calls in extensions.
- Set an explicit logger level when a cross-environment diagnostic is tested.
- Run the affected extension test with coverage after changing diagnostics.
