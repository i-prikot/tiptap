# Restore Renovate test compatibility

**Date:** 2026-07-31 16:27
**Files:** test/scripts/run-smoke-test.test.mjs, test/scripts/generate-icons.test.mjs, test/renderer/render-document.test.ts, test/renderer/__snapshots__/render-document.test.ts.snap
**Severity:** medium

## Problem

The Renovate pull request failed while collecting two script tests because Vite
tried to bundle their `node:test` imports in the default `happy-dom`
environment. The same update also changed KaTeX's generated class names,
invalidating the renderer HTML snapshot.

## Root Cause

The script tests require Node built-ins but did not opt out of the global
browser-like Vitest environment. Vitest 4 applies that environment during
module transformation, where `node:test` cannot be bundled. KaTeX 0.18.1
renames internal CSS classes in otherwise equivalent generated HTML.

## Solution

Declared both script tests as Node-environment tests and imported their test
APIs from Vitest, matching existing Node test files. Regenerated the math
renderer snapshot using KaTeX 0.18.1 and normalized only the renamed KaTeX
internal class names before snapshot comparison. The Windows symlink fixture
now creates a directory junction, which requires no Developer Mode or elevated
privileges and is still rejected by the generator as a linked ancestor.

## Prevention

- Mark tests that use Node child processes or filesystem fixtures with
  `@vitest-environment node`.
- Import test APIs from `vitest` so tests follow the configured runner.
- Regenerate renderer snapshots in the Renovate dependency-update branch when
  a renderer dependency intentionally changes serialized HTML.
- Use a directory junction for Windows link fixtures when the behavior under
  test is equivalent to a directory symbolic link.
