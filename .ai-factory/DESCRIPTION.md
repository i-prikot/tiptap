# Описание проекта

> Документ отвечает на вопрос «Что представляет собой проект?»: назначение,
> возможности и варианты потребления пакетов. Топология workspace, правила
> зависимостей и контракт интеграции описаны в
> [`ARCHITECTURE.md`](./ARCHITECTURE.md).

## 1. Назначение

Проект — npm-workspaces монорепозиторий с переиспользуемой
**Notion-подобной библиотекой редактора форматированного текста** на Vue 3 и
отдельным статическим рендером документов. Библиотека прежде всего
предназначена для кабинета Tinyfy, которому нужно создавать, хранить и
показывать насыщенные документы: заголовки, списки, таблицы, изображения,
формулы, эмодзи, упоминания и другие блоки.

Редактор поставляется как библиотека, а не как самостоятельное приложение.
Кабинет Tinyfy — основной внешний host-потребитель пакетов: он находится вне
этого репозитория, подключает редактор в собственный интерфейс и владеет
документными данными. Внутреннее приложение playground служит только для
локальной разработки, интеграционной проверки и демонстрации; оно не входит в
путь продуктовой интеграции Tinyfy.

Реализация развивает Vue-версию поведения Notion-like editor на базе Tiptap.
Фактические публичные контракты пакетов и исходный код workspace имеют
приоритет над историческими сведениями о первоначальном шаблоне.

## 2. Workspace-пакеты

| Workspace | Статус | Внешнее назначение |
| --- | --- | --- |
| `@i-prikot/editor-schema` | публикуемый | Версии схемы сохранённых документов, миграции, общие наборы Tiptap-расширений и безопасный для рендерера вход. |
| `@i-prikot/editor` | публикуемый | Vue UI редактора, стабильный фасад `NotionEditor`, локализованный интерфейс и изолированные стили редактора. |
| `@i-prikot/editor-renderer` | публикуемый | Серверобезопасное преобразование сохранённого JSON документа в статический HTML. |
| `@i-prikot/playground` | private, не публикуется | Демонстрационное и интеграционное приложение для проверки публичных интерфейсов библиотек. |

Выбор пакета зависит от сценария:

- Для интерактивного редактирования во Vue используется `@i-prikot/editor` и
  один из его публичных CSS-входов.
- Для публикации или предпросмотра уже сохранённого JSON без Vue UI
  используется `@i-prikot/editor-renderer` вместе с нужными CSS-ресурсами.
- `@i-prikot/editor-schema` подключают только тогда, когда приложению нужны
  типы, версии схемы, миграции или общие расширения. Потребителям не следует
  импортировать внутренние пути из `packages/*/src`.

## 3. Основные возможности редактора

### Форматирование и структура

- Жирный, курсив, подчёркивание, зачёркивание, код, верхний и нижний индекс.
- Цвет текста и выделения, ссылки, типографика и плавающая панель выделения.
- Абзацы, заголовки, цитаты, блоки кода, списки, задачи, разделители и отступы.
- Выравнивание текста и блоков, фон блоков, inline- и block-формулы KaTeX.
- Оглавление: боковая панель и вставляемый блок с якорной навигацией.

### Медиа, таблицы и быстрый ввод

- Загрузка, изменение размера, подпись, выравнивание и скачивание изображений
  через адаптер, который предоставляет host.
- Эмодзи по `:`, упоминания по `@` и слэш-меню по `/`.
- Таблицы с resize колонок, ручками строк и столбцов, контекстными операциями,
  drag-перестановкой, объединением ячеек и настройками ширины.
- Плавающий, мобильный и drag-меню для работы с блоками.

### Граница Combobox

- Исходное поведение Ariakit Combobox с фильтром для screen reader исключено из
  текущей области `@i-prikot/editor`.
- Действующие меню подсказок для `/`, `@` и `:` сохраняют собственную
  клавиатурную навигацию и доступные связи `listbox` / `option` /
  `aria-activedescendant`; их поведение не меняется.
- Ariakit не является зависимостью или публичным контрактом пакета. Эта
  продуктовая граница не добавляет runtime-логирование и не означает обещания
  принять Ariakit в будущем.
- Вернуться к фильтрации для screen reader можно только по отдельно одобренной
  спецификации с целевыми сценариями, критериями доступности, публичной
  конфигурацией и требованиями совместимости с существующими меню и host.

### Дополнительные режимы

- Светлая и тёмная темы на CSS-токенах.
- AI-функциональность не поставляется библиотекой и не использует Tiptap Pro
  AI; возможное развитие — только отдельно одобренное собственное
  AI-расширение Tinyfy.
- Совместное редактирование не входит в текущую область продукта и может
  рассматриваться только после появления необходимой бэкенд-части Tinyfy.
- Статический рендер сохранённых документов с KaTeX без загрузки Vue-редактора.

## 4. Технологический обзор

- **Пакетный менеджмент:** npm workspaces.
- **Интерактивный UI:** Vue 3, TypeScript, Vite и Tiptap v3.
- **Документная модель и хранение:** Tiptap JSON с полем `schemaVersion`;
  версии схемы и миграции находятся в `@i-prikot/editor-schema`, а каноничное
  содержимое хранит бэкенд Tinyfy на Node.js и MySQL.
- **Совместное редактирование:** не поддерживается в текущем продукте;
  зависимости Yjs, `@hocuspocus/provider` и Tiptap Cloud не являются частью
  публичных возможностей библиотеки.
- **Статический рендер:** `@tiptap/html`, `happy-dom` и KaTeX в
  `@i-prikot/editor-renderer`; HTML является производным результатом рендера
  сохранённого JSON, а не источником истины документа.
- **Качество:** ESLint, Prettier, Vitest, Playwright и TypeScript project
  references.

## 5. Структура репозитория

```text
.
├── packages/
│   ├── schema/                 # @i-prikot/editor-schema
│   ├── editor/                 # @i-prikot/editor
│   └── renderer/               # @i-prikot/editor-renderer
├── apps/
│   └── playground/             # @i-prikot/playground (private)
├── test/                       # unit и integration tests
├── e2e/                        # browser scenarios
├── scripts/                    # workspace и release verifiers
└── .ai-factory/                # инженерные соглашения и документация
```

Публикуемыми библиотеками являются только пакеты scope `@i-prikot`.
`@i-prikot/playground` — development-only приложение и не является вариантом
интеграции для Tinyfy или другого продукта.

## 6. Контекст потребления

Бэкенд Tinyfy на Node.js и MySQL владеет идентификатором документа, каноничным
Tiptap JSON с полем `schemaVersion`, его хранением и жизненным циклом страницы.
Он передаёт `NotionEditor` входные данные и получает изменения через публичный
компонентный контракт. Для server-side или publish-time представления тот же
сохранённый JSON передают в `@i-prikot/editor-renderer`, который создаёт
производный статический HTML, а не сохраняемое каноничное содержимое.

Это разделение оставляет host-секреты, аутентификацию и инфраструктуру хранения
за пределами публичной ответственности библиотечных пакетов. Контракты событий,
component ref, тема, локализация, внешние сервисы и требования к очистке HTML описаны в
[`ARCHITECTURE.md`](./ARCHITECTURE.md).

## 7. Конфиденциальность и диагностика

Пакеты не должны содержать host-секреты, долгоживущие токены или статическую
конфигурацию внешних сервисов. Краткоживущие учётные данные и URL получения
токенов предоставляет host.

`developmentDiagnostics` — опциональная development-диагностика с
редактированными событиями жизненного цикла. Она не должна записывать содержимое документа,
JSON/HTML, токены, значения локализации или полные каталоги сообщений.

## 8. Публикация

- Публикуемые workspace-пакеты: `@i-prikot/editor-schema`,
  `@i-prikot/editor` и `@i-prikot/editor-renderer`.
- Публикация выполняется в GitHub Packages для scope `@i-prikot`.
- `TINYFY_PACKAGES_TOKEN` — имя GitHub Environment secret, а не npm scope.
